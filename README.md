# سَنَد

منصة عربية لمساندة المعرّفين بالإسلام في خمس محطات: استعدّ، أعِدّ، أنتِج، انشر، مارِس.

**الحالة الحالية، 6 أكتوبر 2026:** تعمل المحطات الخمس بوظائف محلية محددة: تحقّق محافظ، استرجاع بيّنات، بطاقات مصدر، مشاركة وتدريب أساسي. التوليد الاختياري مكتمل برمجيًا لكنه مغلق على الموقع الحي. أُدخل ملف الاختبارات المراجع: 106 حالات مقبولة، ونتيجة المدقّق المحلية على dev هي 43/47 (91.49%)؛ لا تمثل تقييمًا نهائيًا. الفهرس الدلالي الكامل غير منجز بسبب حصة Google. بدأ كتابة كود التطبيق في 4 أكتوبر 2026، وتواريخ المصادر محفوظة كما وردت دون ادعاء تاريخ إعداد غير مثبت.

## التشغيل على Windows

المتطلبات: Node.js 20.9 أو أحدث وnpm، وPython مع openpyxl لتحويل المصادر فقط.

```powershell
cd "C:\Users\Windows 11\Desktop\sanad\sanad"
npm ci
npm run dev
```

افتح http://127.0.0.1:3000. وظائف المحطات الافتراضية تعمل دون مفتاح API؛ يُستخدم المفتاح للفهرسة وللتوليد الاختياري إذا فُعّل صراحة في بيئة الخادم.

## التحقق

```powershell
npm test
npm run lint
npm run build
```

بعد البناء، شغّل `npm start` في نافذة وأمر `npm run test:smoke` في نافذة أخرى. تتحقق اختبارات الصفحات من المسارات والشريط التحذيري وRTL و404. تختبر اختبارات البيانات سلامة المراجع وتصنيفات المصدر واكتمال القرآن والترجمات، ولا تقيس الدقة الشرعية أو دقة نموذج.

## البيانات

مصادر Excel في `sources/`، والمخرجات في `data/`. يُسمح بتجديد المخرجات بواسطة المحوّل فقط:

```powershell
python -m pip install openpyxl
python build_data.py
```

التحويل الأخير: 54 حديثًا، 21 صفًا في خريطة الأحكام، 200 حالة اختبار (50 dev و150 test)، 25 سؤال بيّنات، 83 مصطلحًا، 4 جماهير، 6236 آية بكل من النص العربي وترجمات en وbn وur. سلّم المستخدم 106 حالات موسومة «مقبول» وأكد مراجعتها؛ 94 حالة باقية غير مراجعة. خانة اسم المراجع فارغة في 16 حالة مقبولة، ويظل توثيقها مطلوبًا. لم نضع «مقبول» أو أسماء المراجعين آليًا.

التخريجات التسعة الخالية من الحكم تحفظ كمراجع ولا تعرض أحكامًا. تحتاج أسماء الجمهور a-02 وa-03 إلى مراجعة توافقها مع اللغة والخلفية؛ أُخفي هذان الخياران مؤقتًا من واجهة التدريب ولم تُعدّل البيانات المصدرية.

## التقنيات

- Next.js وReact: الصفحات والتنقل والتصيير.
- TypeScript: التحقق من الأنواع.

يحدد package-lock.json الإصدارات المثبتة لضمان إعادة البناء. أضيف SDK الخاص بـ Gemini وZod للفهرسة والتحقق من خرج النموذج الاختياري. المحطات الخمس منشورة وعاملة، وليست واجهة تعريفية فقط.

فحص الاعتماديات في هذه المرحلة: لا ثغرات معلنة في حزم الإنتاج (`npm audit --omit=dev`). توجد 5 تنبيهات عالية في سلسلة اعتماد أدوات ESLint بسبب braces 3.0.3، دون إصدار مصحح متوافق متاح وقت الفحص. هذه أدوات تطوير لا تدخل في تشغيل الموقع؛ يلزم متابعة إصلاح المنبع.

## المنهج والخصوصية

النموذج يقترح، والمصدر وحده يحكم. أحكام الحديث والآيات والمراجع تؤخذ من المصادر فقط. اختلاف تصنيفات الأحكام يظهر كله. عدم العثور على نص ليس حكمًا بوضعه. النصوص الشخصية لا تخزّن على خادم التطبيق، والبطاقات المستقبلية تحفظ محليًا. لا توجد حسابات أو تحليلات تتبع في النسخة الأولى.

تفاصيل المصدر والترخيص في `sources/quran/SOURCES.md`. أكد صاحب المشروع إذنه بنشر نصوص بيّنات؛ ينبغي الاحتفاظ بإثبات الإذن عند التقديم إذا طُلب. تقرير REVIEW.md مراجعة قديمة؛ تتقدم عليه البيانات الحالية وPLAN.md.

## النشر على Vercel

1. بعد رفع المشروع إلى مستودع GitHub، افتح Vercel واختر Add New → Project.
2. اربط حساب GitHub واختر المستودع `mohammadsajjadbd2026/sanad`.
3. اختر Next.js، واجعل Root Directory جذر المستودع (`./`).
4. اترك Build Command على `npm run build` وOutput Directory على إعداد Next.js الافتراضي.
5. انشر الواجهة الأولى دون مفاتيح. قبل تفعيل Gemini أضف GEMINI_API_KEY وGEMINI_MODEL وGEMINI_EMBED_MODEL في Settings → Environment Variables ثم أعد النشر.
6. لا تستخدم NEXT_PUBLIC_ لمفاتيح Gemini ولا تضع المفتاح في المحادثة أو Git. محليًا استخدم `.env.local` اعتمادًا على `.env.example`.
7. النسخة الحية الحالية: https://sanad-lovat-gamma.vercel.app/ . لا تضبط `GEMINI_RUNTIME_ENABLED=true` قبل التحقق من ضبط إنفاق الزوار؛ إعداد المفتاح وحده لا يفعل الطلبات التوليدية.

ملفات المصادر وdata تبقى ملفات خادم ولا توضع في public. لا تشمل النسخة الأولى صفحة لاستعراض نصوص بيّنات.

## المرحلة الثانية: المصادر والبحث الدلالي

أضيفت محمّلات محمية بوحدة `server-only` للقرآن وترجماته والأحاديث وبيّنات، مع التحقق من البنية بواسطة Zod والتوقف عند مصدر ناقص أو غير صالح. نصوص العرض تعود كما هي من المصدر. نسختا التطبيع للبحث والمقارنة منفصلتان؛ تطابق البحث وحده لا يثبت صحة اللفظ أو الحكم.

أضيف SDK الرسمي `@google/genai` لإنشاء البصمات، و`@next/env` لتحميل إعدادات الخادم، و`server-only` لمنع استيراد وحدات المصادر والخدمات في مكونات العميل.

### ضبط الخدمة محليًا

ضع المفتاح في `.env.local` (مستبعد من Git)، واختر نموذجًا متاحًا لحسابك:

```dotenv
GEMINI_API_KEY=ضع_مفتاحك_محليًا
GEMINI_EMBED_MODEL=gemini-embedding-2
GEMINI_EMBED_DIMENSIONS=768
```

`GEMINI_MODEL` مخصص للنموذج التوليدي في المرحلة التالية. لا يحتاجه بناء البصمات. أمر `npm run env:check` يطبع وجود الإعدادات فقط دون قيم المفتاح.

### أوامر الفهرسة بالترتيب

```powershell
npm run embeddings:plan
npm run embeddings:sample
npm run embeddings:build
```

الأول لا يتصل بـ API. الثاني يفهرس عينة من 20 مرجعًا موزعة على أنواع المصادر. الثالث يكمل جميع المصادر ويعيد استخدام عناصر العينة المحفوظة. الفهرسة ترسل النصوص المرجعية اللازمة إلى Google عبر المفتاح، وقد تحتسب تكلفتها بحسب خطة الحساب. لا ترسل بيانات المراجعين أو ملفات الاختبار أو ملفات Excel/PDF كاملة.

الفهرس يحتوي مستندًا واحدًا لكل مرجع: 6236 آية مع ترجمات معانيها، و54 حديثًا مع صيغه المترجمة، و25 سؤالًا من بيّنات. الأجوبة تسترجع من المصدر لاحقًا. يرسل Embedding 2 نصًا واحدًا لكل طلب لأن إرسال قائمة قد يدمج مراجع مختلفة في بصمة واحدة. مهمة البحث مضمنة في صيغة الإدخال وفق توثيق Google. الصيغ الأصلية لا تتغير.

البصمات في `data/embeddings/` ملفات مشتقة، وليست نصوصًا أو أحكامًا جديدة. تحفظ في أجزاء من 100 عنصر مع بصمة للمصدر واسم النموذج والأبعاد. يُرفض استعمال فهرس قديم بعد تغيير المصادر أو النموذج. لا يفعّل `active.json` إلا بعد اكتمال التشغيل الكامل، وتُحفظ كل استجابة ناجحة قبل الطلب التالي. إعادة التشغيل تستأنف الناقص فقط. القفل `build.lock` يمنع التشغيل المتزامن، وقد يلزم إزالته يدويًا بعد التأكد من توقف عملية انقطعت قسرًا.

طلبات الخدمة متتابعة بفاصل ثانية افتراضيًا لتخفيف ضغط الحصة. يمكن تغيير حجم دفعة المعالجة والفاصل بأمر مثل `npm run embeddings:build -- --batch-size 5 --delay-ms 10000`. تعاد الأخطاء المؤقتة 3 مرات كحد أقصى؛ أخطاء المفاتيح والصلاحيات لا تعاد. لا تخفض الفاصل إلا ضمن حصة حسابك.

تقارير `results/embeddings-sample.json` و`results/embeddings-full.json` تنشأ عند نجاح التشغيل الفعلي فقط. نجحت عينة 20 عنصرًا، ثم توقفت الفهرسة الكاملة عند 1260/6315 بسبب رد HTTP 429 من Google، حتى بعد الإبطاء إلى طلب كل عشر ثوانٍ؛ العناصر المكتملة محفوظة، لكن الفهرس غير مفعّل. استئنافها يحتاج معرفة الحصة الفعلية أو انتظار تجددها، ولا ينبغي التكرار المستمر. نجاح فهرسة العينة ليس تقييمًا لدقة المدقّق.

## وظائف نسخة العرض الحالية

- `/draft`: مطابقة محافظة للنصوص المسجلة، حكم الحديث بلفظه من المصدر، تقرير قابل للطباعة إلى PDF، ملفات TXT/DOCX تُقرأ في المتصفح. ضع الاقتباس في سطر مستقل أو بين علامتي اقتباس لتتحسن المطابقة. عدم العثور لا يعني الوضع.
- `/produce` و`/publish`: بحث لفظي في النصوص، بطاقة من نص مصدر ثابت موثوق، قالبان PNG، نسخ ومشاركة WhatsApp أو نظام الجهاز، حفظ مرجع البطاقة في المتصفح وإعادة التحقق منه عند التصدير. لا تُصدّر الأحاديث الضعيفة أو المختلف عليها. تظهر إرشادات القاموس المطابقة للنص العربي أو الإنجليزي للمراجعة فقط؛ لا تغيّر النص. يوجد خيار وصف قصير موسوم «مولّد» بعد اختيار الجمهور وموافقة مستقلة، لكنه مغلق على الموقع الحي حاليًا. لا تُستخدم ملفات الجمهور المتعارضة a-02 وa-03.
- `/practice`: أقرب سؤال بيّنات بالعربية بنص الجواب ورقم الصفحة، باسترجاع لفظي دون إنشاء جواب. لا يُدعى دعم الأسئلة بلغات أخرى حتى تتوافر ترجماتها المعتمدة أو الفهرس الكامل.
- `/prepare`: سؤال من بيّنات وإجابة المستخدم ثم المرجع وتقرير الاقتباسات. النبرة والجمهور اختياران للعرض؛ تقييم Gemini الاختياري موجود برمجيًا لكنه معطّل افتراضيًا.
- يمكن تمكين تغذية راجعة قصيرة مولّدة في التدريب فقط بإعداد `GEMINI_RUNTIME_ENABLED=true` مع `GEMINI_API_KEY` و`GEMINI_MODEL` في بيئة الخادم، بعد ضبط حد الإنفاق في Google. المستخدم يختار موافقة منفصلة قبل إرسال إجابته وجواب بيّنات إلى Google. تتحقق الخدمة من JSON ومحاولة ثانية ثم تخفي النتيجة عند الفشل. يخرج النموذج درجات ورمز نصيحة محدودًا؛ النص الإرشادي ثابت، ولا يصدر عن النموذج آية أو حديث أو مرجع أو حالة تحقّق. الافتراضي `false`، وهو إعداد الموقع الحي حاليًا.
